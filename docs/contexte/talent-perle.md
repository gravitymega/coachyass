**Architecture :**
- `talent-perle-dashboard/schema.sql` : à exécuter une seule fois dans le nouveau projet Supabase (SQL Editor). Crée 4 tables (`activities`, `photos`, `events`, `partners`), active la RLS avec lecture publique seule (écriture réservée à la clé `service_role`, jamais exposée au client), crée le bucket de stockage public `talent-perle`, et pré-remplit `activities` avec les 5 activités actuelles du site (Soccer, Volleyball, Tennis, Basketball, **Jeu d'échecs** — remplace "Activités culturelles").
- `talent-perle-dashboard/netlify/functions/admin.js` : unique fonction serveur, porte d'entrée pour toutes les opérations (list/create/update/delete/upload). Vérifie l'en-tête `x-admin-password` contre `DASHBOARD_PASSWORD` (variable d'environnement Netlify) à chaque appel, puis parle à Supabase avec la clé `service_role` (également en variable d'environnement : `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`).
- `talent-perle-dashboard/index.html` : page d'accès (mot de passe) + 4 onglets (Activités, Photos, Événements, Partenaires), chacun avec un formulaire d'ajout (upload d'image direct vers Supabase Storage via la fonction) et une liste avec suppression/masquage.
- `talent-perle-site/index.html` : lit maintenant Supabase en lecture seule (clé `anon`, publique par design) pour peupler dynamiquement la grille d'activités **et** le menu déroulant du formulaire d'inscription (une seule source de données pour les deux — toute activité ajoutée par Karim apparaît automatiquement dans le formulaire), ainsi que Galerie/Calendrier/Partenaires. Config dans la variable `TP_SUPABASE` (bloc `<script>` dédié, juste après `TP_SHEET_URL`) — **vide par défaut**, le site utilise alors un tableau JS `FALLBACK_ACTIVITIES` statique (les 5 mêmes activités) et les sections Galerie/Calendrier/Partenaires gardent leur contenu d'exemple statique, donc aucune régression tant que Supabase n'est pas branché.

**Reste à faire côté utilisateur/Karim pour activer le dashboard :**
1. Créer un compte Supabase (gratuit) séparé de l'écosystème Gravity, créer un nouveau projet.
2. Exécuter `talent-perle-dashboard/schema.sql` dans son SQL Editor.
3. Créer un site Netlify pour `talent-perle-dashboard/` (base directory = `talent-perle-dashboard`, publish = `.`), comme pour `talent-perle-site/`.
4. Sur ce nouveau site Netlify, ajouter les variables d'environnement `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API → `service_role`, secret) et `DASHBOARD_PASSWORD` (mot de passe au choix pour Karim).
5. Sur `talent-perle-site/index.html`, remplir `TP_SUPABASE.url` et `TP_SUPABASE.anonKey` (Project Settings → API → `anon` `public`, celle-là est sans danger à exposer côté client).
6. Si l'URL du dashboard n'est pas `talent-perle-dashboard.netlify.app` une fois le site créé, mettre à jour le lien "Accès administrateur" dans `talent-perle-site/index.html` (section Espace membre).
